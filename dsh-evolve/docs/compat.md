# DSH 宿主兼容性

DSH Harness Evolve 的 bundle 使用当前宿主提供的 DSH、Cordis 和 Schemastery。发布包不把这些包作为普通生产依赖，不携带另一套核心；源码开发依赖固定版本仅用于构建复现。

## 已检查版本

| DSH | dev.13 验证范围 |
|---|---|
| `0.2.1-rc.2` | 新 Profile 安装与启动、默认组件激活、状态接口、旧依赖形态升级、导入故障隔离 |
| `0.2.1-rc.3` | 新 Profile 安装与启动、默认组件激活、状态接口、旧依赖形态升级、导入故障隔离 |

这些是无模型的安装与启动检查，不代表所有真实任务或未来 DSH 版本已验证。可选的 Loop 替换默认关闭，需要单独确认行为兼容性。

## 加载状态

入口检查使用到的原生 API，并核对关键服务的宿主身份。缺少服务时等待；模块导入、配置或初始化不兼容时停用 Evo，撤销本组初始化副作用，保留 DSH 服务。面板和 `/evolve/compatibility` 提供具体原因。

旧版升级时包管理器可能保留 SDK 缓存；Evo 从当前宿主解析依赖，不删除用户 Profile 文件。恢复兼容环境后重新加载整个 Evo 组或重启 Profile，保存的策略与历史不因此清除。

这道边界保护 Evo 加载与初始化，不承诺拦截宿主加载器、Node 启动或所有第三方异步错误。直接调用库入口的 SDK 使用者负责其异常处理。

## 独立 worker

默认后台 worker 在 DSH 宿主内运行。宿主退出后继续学习的独立 worker 需要另行配置版本一致的 DSH SDK；不要为了该可选模式向 Desktop Profile 安装第二套核心。

仓库名为 `dsh-harness-evolve`；内部包名 `@dsh-evolve/*`、命令和 `.dsh-evolve/` 数据标识保持兼容。
